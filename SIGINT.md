[[SIGINT]] is the signal generated when the user presses **`Ctrl+C`**. Its default action is to immediately terminate the process, but in the case of a shell, this behavior must be modified. If the shell itself exited on `Ctrl+C`, the user would lose their working environment entirely, which is not the expected behavior. Instead, an interactive shell like Bash simply clears the current input line and displays a fresh prompt, allowing the user to continue without disruption. Minishell must mimic this behavior by installing a custom handler for [[SIGINT]] in the parent process.

When a child process is running, however, the behavior is different. In Bash, pressing `Ctrl+C` does not just refresh the prompt; it **kills the running program**. To reproduce this, Minishell should reset the child process’s [[SIGINT]] handling back to the default before executing with `execve()`. This way, pressing `Ctrl+C` will terminate the child as expected, and once the process ends, the shell regains control and shows the prompt again.

Correct handling of [[SIGINT]] therefore requires distinguishing between the **parent shell** and its **children**. The parent must override the default action to stay alive and refresh the prompt, while children must inherit the default so programs behave consistently with Bash. This dual behavior ensures Minishell provides a smooth, intuitive experience that matches the standards of a real shell.
