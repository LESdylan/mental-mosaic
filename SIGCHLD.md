[[SIGCHLD]] is the signal sent by the kernel to a parent process whenever one of its child processes terminates or stops. By default, this signal is ignored, but shells rely on it to manage the lifecycle of the commands they launch. When a child finishes, the parent must collect its exit status using `wait()` or `waitpid()`. If this is not done, the system will leave the child in a “zombie” state, consuming process table entries until the parent cleans it up. For a shell, avoiding zombie processes is critical to maintain system stability.

In Bash, [[SIGCHLD]]  is implicitly handled since the shell always reaps its children as they exit. Minishell must follow the same principle: whenever a command is executed in a child process, the parent shell must use `waitpid()` to retrieve the child’s status. This not only prevents zombies but also allows the shell to store the exit code in `$?`, ensuring that subsequent commands depending on return values behave as expected.

Although you typically do not need a custom signal handler for [[SIGCHLD]]  in Minishell, the concept is central to understanding why reaping children is necessary. Properly handling terminated processes ensures that the shell behaves reliably, cleans up resources, and accurately reflects the execution state of its child commands.
