[[SIGQUIT]] is the signal generated when the user presses **`Ctrl+\`**. Its default action is to terminate the process and produce a _core dump_, which is useful for debugging but disruptive in an interactive shell. In Bash, pressing `Ctrl+\` at the prompt does nothing—the shell simply ignores it. This behavior ensures that the user cannot accidentally kill their shell session with this key combination. Minishell must replicate this by explicitly ignoring [[SIGQUIT]] in the parent process.

The behavior is different when a child process is running. If the user presses `Ctrl+\` while executing a program, Bash forwards the signal to the child. The child then receives [[SIGQUIT]] usually terminates, and prints “Quit (core dumped)” before the shell regains control. To achieve the same effect in Minishell, the child process must restore [[SIGQUIT]] to its default behavior before executing the program with `execve()`.

This separation of responsibilities is essential: the **parent shell** ignores [[SIGQUIT]] to remain stable, while the **child processes** respect the default behavior so that user expectations match those of a real shell. Without this distinction, either the shell could crash unexpectedly, or the child processes would fail to respond correctly to user input.
